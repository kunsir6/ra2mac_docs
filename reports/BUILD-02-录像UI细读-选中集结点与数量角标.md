# BUILD-02 录像 UI 细读：选中之后、数量角标、以及其他能看出来的

**日期**：2026-11-12
**输入**：同一份录像 `SVID_20261112_011757_1.mp4`（720×448 / 30fps / 84.9s / 5.8MB ≈ 546 kbit/s）
**一句话**：能确认的是「**选中工厂后从出口拉一条绿色虚线到集结点**」（我们是 1px 实线）；数量角标在这段
录像里**读不出来**（像素预算不够，见 §4），只能给出对齐方案。另附侧栏逐段结构实测，供观感对账用。

---

## 1. 先算一笔像素预算：这段录像能看清什么

| 项 | 数值 | 含义 |
|---|---|---|
| 输出分辨率 | 720×448 | 手机横屏录制，顶部 8px 是黑边 |
| 码率 | 5.8 MB / 84.9 s ≈ **546 kbit/s** | 抖音二次压缩级，细节被抹得很干净 |
| 侧栏宽度 | **59 px**（x≈658–717） | 占屏 8.2% |
| 单个建造格 | **≈28×26 px** | 正版 cameo 是 60×48 → 被缩到 **0.47 倍** |
| 正版数字字形 | GAME.FNT 约 8×12 | 缩 0.47 后 ≈ **4×6 px**，再经 546 kbit/s 压缩 → 基本归零 |

所以本报告把结论分成两档：**能判定的**（几何、颜色、出现时机、相对关系）和**只能给方案的**
（cameo 上的 2~3 像素级微 UI，比如数量角标）。

## 2. 侧栏逐段结构（74s 时刻，6 倍放大实测）

从上到下：

1. **顶部窄金属牌**：极小字（版式标签），高度 ~10px。
2. **资金牌**：金属条 + **红色七段数字**（5 位，本片多数时刻可辨出前两位是 `1`、中间有 `5`）。
3. **雷达小地图**：金框，**未探索区域是纯黑**（不是灰），已探索区显示地形，中间一个细框光标。
   片中出现过两次成片黑区 → 黑幕是按格子硬遮的，没有"半探索"渐变。
4. **电力条**：雷达下面另一条金属牌，同样红色数字/刻度。
5. **标签页**：**4 个圆角小按钮**（红、红、白灰、黄）——对应 建筑 / 防御 / 步兵 / 车辆。
6. **建造格**：**2 列 × 约 14 行**，单格 28×26；本片刻里最多只有前 3 行有图标，其余是深色空槽。
7. **底部**：一条金属横条 + 中间一个白色梯形按钮（修理/卖出位）。
8. **左缘一条暗红竖条** = 玩家色（苏军红）。

> 观感对账提醒：这块侧栏**只有正版的一半大小**（cameo 28×26 vs 60×48，侧栏占屏 8.2% vs 正版资产
> `side1.shp` 的固定 168px）。拿它做"正版像素基准"会失真，只能用来判"有没有 / 什么颜色 / 什么时候出现"。

## 3. 选中之后显示什么：**集结点绿色虚线**（本轮最硬的发现）

在 t≈62.25、71.6–72.5、76–78、83.0 四处，画面里出现一条**绿色虚线**。把最大连通块打成字符位图后，
形状是确定的（下例为 t=72.2s，`#`=满足 g>150∧r<120∧b<120 的像素）：

```
.............................####.     ← 4 像素一段
.............................##...
.........................####.....
.........................##.......
.......................##.........     ← 2 像素间隙
....................###...........
.................#.##.............
.................##...............
.............####.................
.............##...................
.........####.....................
.........##.......................
.....####.........................
.....##...........................
.####.............................
.##...............................
```

- **实/空比 = 4px 实 + 2px 空**，线宽约 **2px**，方向为斜向（跟随地形等距投影）。
- 长度会变：同一锚点下 16px（t=71.6）→ 31px（t=72.2）→ 47px（t=77.9）——**端点跟着点选位置走**。
- 起点固定落在**战车工厂的出口**（72.2s 那张 7 倍放大里，线尾正对工厂卷帘门外的空地），
  另一端是空地/目标点，**没有旗子、没有箭头**。
- 颜色（压缩后实测核心像素）≈ **RGB(85,175,60)** 的亮黄绿；压前的真值应更纯。

**判定**：这就是"选中生产建筑 → 集结点指示线"，且**每帧都在重画、会随集结点移动**。
（保留一点不确定性：本片是缩放端口，也可能把同一条虚线复用成"拖拽指令指示"。但起点钉在工厂门口
这一点与集结点语义一致，且我们自己的实现在同一位置画同色线，所以按集结点对齐是安全的。）

### 与我们现状的差距

`src/simulation/production/RuntimeFactoryRallyUi.inl` → `drawRuntimeFactoryRallyPoint()`：

```cpp
HPEN line = CreatePen(PS_SOLID, 1, RGB(104, 230, 104));
MoveToEx(dc, origin.x, origin.y, nullptr);
LineTo(dc, destination.x, destination.y);
```

- 颜色接近（104,230,104 vs 实测 85,175,60，都是亮绿系）；
- **线型不同：我们是 1px 实线，正版是 2px 的 4/2 虚线**；
- 起点取的是"稳定生产门口"（代码注释也是这么写的），和录像一致；端点不带旗子，也一致。

→ 这是一处**低风险、有实证**的可改项：`PS_SOLID` 改成分段画（每 6px 画 4px），笔宽 2。

## 4. 数量角标：这段录像判不了，但可以把方案摆清楚

**为什么判不了**：见 §1 的像素预算——正版 8×12 的数字缩到 4×6 后，再进 546 kbit/s 的编码，
每个笔画只剩 1 个像素左右的能量。我把 72–82s 的"坦克格"按 24 倍放大逐帧看过：能看到图标本体、
能看到进度遮罩（半透明、斜向边界），**看不到任何数字或角标底框**。

同样的道理，**"就绪"两个字在 cameo 上的样子也读不出来**（这也是上一轮做角标时只能靠你的口述定样式）。

**我们现在的实现**（`RuntimeShell.cpp` 侧栏 cameo 绘制，仅步兵/车辆且数量>0）：

```
外框   iconRect.right-25 .. right-3     （22×16，贴右上角）
       iconRect.top+3   .. top+19
底色   RGB(2,5,8) 实心
描边   RGB(180,228,252) 1px
数字   RGB(232,248,255)，DT_CENTER 居中
```

**三种对齐方案**（挑一个我就改）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 保持现状 | 深色小框 + 青边 + 数字 | 最易读，但比正版"多画了一个框" |
| B. 去框留号 | 只画数字，`(1,1)` 黑投影，右上角 | 更接近老引擎的"裸数字"，小图标上略难读 |
| C. 折中 | 去描边，留极暗底（α≈60%）+ 数字外描黑边 | 兼顾可读与克制 |

从"正版是引擎用 GAME.FNT 直接叠数字、没有额外底框"这个引擎侧事实看，**B/C 更像正版**；但缺少
本片实证，建议你按手感拍。

## 5. 其他能看出来的

1. **建造中**：格子上是**半透明金色遮罩 + 斜向边界**（时钟扫描），不是灰掉。
   我们已经有 `drawRuntimeBuildProgressClockOverlay`（`gclock2`，55 帧）——这一点是对齐的。
2. **就绪**：格子**全亮无遮罩**，同时页面上**没有**出现屏幕中央的大提示（本片没有）。
3. **空槽极多**：本片该页只有 5 个可建项，侧栏 14 行里有 9 行空槽——正版就是"大方块空槽"，
   不存在"隐藏空槽"。
4. **电力条也在用红色七段数字**，不是正版常见的横条填充——这是该端口自己的画法。
5. **雷达黑幕是纯黑块**，边界是格子状的直角，没有过渡。
6. **底部有策划字幕**（`点赞·收藏·关注`、`第6…` 等）压在地图下缘，分析时别当成 UI。
7. **手机状态栏**（`01:17`、`137 K/s`）在画面最上方——说明这是手机录屏，不是原生 720p 输出，
   这也解释了为什么整体比例是 720×448 这种非标准尺寸。
