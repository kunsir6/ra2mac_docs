# FIX-02 compat 实现 CP1252 解码

> 日期：2026-11-12
> 计划条目：fix-plan.md 的 M-01
> 源码提交：`b2ee6fc`
> 关联：修掉了 `build` 这条 known-red 的**第一个**阻塞点（语义音频探针）

## 现象

零售 ini（`evamd.ini` 的 `Text=`、`rules.ini` 的字符串表）是 Windows-1252 编码，
`0x85` 是省略号、`0x91/0x92` 是单引号、`0x93/0x94` 是双引号。macOS 侧读出来之后：

1. 先按 UTF-8 试解 → 这些字节不是合法 UTF-8，`MultiByteToWideChar(CP_UTF8,
   MB_ERR_INVALID_CHARS)` 返回 0（这是正确的，调用点就是靠这次失败判定"不是 UTF-8"）。
2. 回落到 CP1252 → `codePageSupported` 直接拒绝，再返回 0。
3. 调用点只好逐字节 widen → `0x85` 变成 `U+0085`（NEL 控制字符），
   字幕里显示为乱码方块。

`build` 回归条因此常驻红：`semantic audio probe: … evaTextEncoding=no …`。

## 根因

`compat/win32/src/RuntimeWin32CompatProcess.cpp` 的码页策略是「只实现 UTF-8」：
`codePageSupported` 只放行 `CP_UTF8 / CP_ACP / CP_OEMCP`，其余一律
`ERROR_INVALID_PARAMETER`。这条策略本身是对的——把未知码页当 UTF-8 解会产出
"看起来合理的错字"，比失败难查得多。**但 CP1252 不是未知码页**，它是有确定
单字节映射表的，零售资产全部依赖它。

## 改法

全部内聚在 `RuntimeWin32CompatProcess.cpp`，不碰调用点（`widenRuntimeSubtitleText`
早就写好了 1252 回落分支，只是一直拿不到 0 以外的返回值）：

| 新增 | 作用 |
|---|---|
| `cp1252HighTable()` | `0x80–0x9F` 的 32 项映射表；5 个未定义位置（81/8D/8F/90/9D）→ `U+FFFD`，与 Windows 行为一致 |
| `cp1252ToUnicode(byte)` | `0x00–0x7F` 与 `0xA0–0xFF` 恒等（Latin-1 区），只有 `0x80–0x9F` 查表 |
| `unicodeToCp1252(code, out)` | 反向；表内可逆，不可映射时给 `lpDefaultChar` 并置 `usedDefault` |
| `codePageSupported` | 放行 `1252`（`CP_ACP`/`CP_OEMCP` 仍按 UTF-8，不动既有语义） |
| `MultiByteToWideChar` 1252 分支 | 一字节一字符；保留 Windows 的「负 cbMultiByte = NUL 计入」语义 |
| `WideCharToMultiByte` 1252 分支 | 严格模式（`WC_ERR_INVALID_CHARS`）下不可映射必须失败，否则调用点会拿着带 `?` 的字节写文件 |

**为什么不顺手把 `CP_ACP` 也改成 1252**：本项目里 `CP_ACP` 的调用点期望的是
macOS 的 UTF-8 语义（菜单/网络等文本路径），改成 1252 会把这些路径整体打错。
CP1252 只在明确传 `1252` 的零售资产路径上生效，这是最小面。

## 验证

- `--build-smoke-test`：失败点从 `semantic audio probe: … evaTextEncoding=no`
  后移到 `real music playback probe: … mci=error-306`。
  说明**语义音频探针（含编码断言）已经通过**，卡住的是下一段。
- 全量回归：`PASS=5 KNOWN-RED=6 RED-NEW=0`，条数与基线一致（`build` 仍
  KNOWN-RED，但原因换了，`known-red.tsv` 的 reason 已同步改写）。

## 新的阻塞点（登记为 env-gap，非本轮引入）

`mci=error-306` 是 MCI 设备不可用（`MCIERR_` 系）。macOS 侧 compat 没有 MCI
后端，这条探针按现定义在 macOS 永远不会绿——与 `campaign` 的 Bink 缺视频同类，
属于「资产/平台缺口被当成产品缺陷判红」。应该改成：MCI 探针在 macOS 跳过并
打印 `skipped(no MCI backend)`，而不是让整条 `build` 红。
