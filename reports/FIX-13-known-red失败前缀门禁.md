# FIX-13 给回归门禁补一道「红的是同一件事」的闸

> 第 12 轮（2026-11-12）。开工基线 `PASS=10 KNOWN-RED=1 RED-NEW=0`（`20261112-200207`），
> 收口 `10/1/0`（`20261112-200531`），零新回归。本轮唯一的在册简单项是 S-12，已落地。
> 本轮不改任何产品代码——改的是**判定器**。

## 一、为什么要改：三态判定只保证「红」，不保证「红的是什么」

第 10 轮踩过一次：`interaction` 本来就红（登记原因：建筑 footprint 命中失配），
`ffdd7c5` 把游戏速度从 7 档改成 6 档后，断言表没跟上，交互冒烟**在更靠前的 ESC 菜单段**就判 fail。
`regress.sh` 只看「退出码非零 + id 已登记」→ 一律报 `KNOWN-RED`。于是：

- 机器判定：零新回归，一切照旧；
- 事实：新回归（速度表过期）**把旧红点顶掉了**，M-12 那条根本跑不到，
  第 10 轮前 25 分钟查的是「M-12 怎么复现不了」。

这不是偶发——只要一条用例常驻红，它就成了一个**黑箱入口**：任何更早的回归都能躲进这个 id 里，
而三态判定看不见。known-red 台账越干净（红条越少），单条黑箱的遮盖面反而越大。
所以这条属于「门禁可信度的地基」，性价比 A。

## 二、改法

`known-red.tsv` 从三列扩到四列，第 4 列是**失败前缀**：

```
id <TAB> 原因 <TAB> status <TAB> 失败前缀
command	两栖船靠岸二次动作后 transportPassengerIds 仍非空；…	code-red	shore unload left tanks aboard
```

`regress.sh` 的判定顺序变成：

1. 退出码 0 → `PASS`；
2. 退出码非 0、id 已登记、**失败前缀出现在本轮失败行里** → `KNOWN-RED`（原样打印登记原因）；
3. 退出码非 0、id 已登记、前缀对不上 → `RED-NEW(cause-changed)`，
   把「登记前缀 / 登记的旧原因 / 本轮失败行」三样一起打印，并**计入退出码**（和新回归同权）；
4. 退出码非 0、未登记 → `RED-NEW`（原行为）。

几个实现细节，都是踩过才写下的：

- **比对必须用未截断的失败行**。原来 `ev` 取出来就先截到 160 字符，直接拿它比前缀会在长失败行上
  假报 cause-changed。现在留 `evfull` 做比对、`ev` 只用于显示。
- **`known_reason()` 必须从命令替换里退出来**。原写法 `reason=$(known_reason "$id")` 在子 shell 里跑，
  两个全局量（原因/前缀）带不回来；改成 `known_lookup()` 写全局量 + 直接 `if` 调用。
- **开跑前预检台账**：缺第 4 列的行逐条告警（`known-red N 条，其中 M 条无前缀门禁`）。
  空前缀的语义是「这一条放弃文案门禁」，这种让步必须在屏幕上说出来，不能静默。
- `$id` 后紧跟全角「」被吞进变量名（`id」: unbound variable`），一律写 `${id}`。
  这条是本项目的老坑，本轮又踩了一次，已在脚本自查里用正则过了一遍。

## 三、自测（两次，都真的跑了）

| 场景 | 做法 | 实测 |
|---|---|---|
| 正常 | 全量 11 条 | `command` → `KNOWN-RED`，前缀命中，10/1/0 |
| 前缀被改坏 | 复制台账到临时 BASE，把前缀改成 `shore unload COLLAPSED THE PIER` | `command` → `RED-NEW(cause-changed)`，1 条计入 NEW，两侧文案都打出 |
| 前缀留空 | 临时台账只留三列 | `command` → `KNOWN-RED` + 预检告警「该条只判红不判原因」 |

自测用 `CONCORD_REGRESS_BASE` 指向临时目录做，没有污染真台账——这条变量上半年加进来就是为了这种场景。

## 四、这条门禁自己的盲区（写清楚，免得下一轮高估它）

1. **只锚「失败行」，不锚退出码语义**。如果某条用例改成「失败但退出码 0」，门禁仍然看不见。
2. **前缀是自由文本**，改断言文案的人必须同步改第 4 列，否则会误报 cause-changed。
   这是有意的：误报一次（人看一眼就能确认）比漏报一次（要一小时才发现）便宜得多。
3. **`pick_evidence` 本身是启发式**（取日志末尾最近一条含 failed/Smoke/done 的行）。
   若某条用例的失败行不在末尾 60 行内，前缀比对会拿到空的/别的行——此时按 cause-changed 处理，
   宁可吵一次。
4. 台账**不校验 status 列**（`code-red` / `env-gap` / `fixture-gap`）。一条 code-red 悄悄被写成
   env-gap 不会被机器拦住。这条留给下一次，成本很低（加一列枚举校验 + 与 `--only` 无关的 lint）。

  `RuntimeTerrainViewportFill.h:75`、`RuntimeRadarPixelStoreWin32.cpp:35` 两处断言现在是真的在判。
  已记进计划 §四，不作为待办重开（避免下一轮照报告再修一遍）。
- **结构守卫基线列着 U-15 已删的两个文件**：守卫要 `--inventory` / `--trace` 产物，
  本机没有，生成入口还没查清 → 新登记 **S-13**（性价比 C，复杂度简单但阻塞在产物）。
- **U-16 的「把部署目标全局 pin 进 CMakeLists」**：321 个测试目标要跟编，其中可能有 macOS 26 符号，
  属复杂，不塞进简单批。

所以本轮的简单批实际只有 S-12 一条可动手项——这不是"挑了一条最省事的"，是简单区真的被前 11 轮清空了
（S-01~S-11 全部完成或废弃）。**不为了凑批量去拆一条中等问题当简单项做**，那样只会把「批量」变成
「一批未经计量的猜测」。
