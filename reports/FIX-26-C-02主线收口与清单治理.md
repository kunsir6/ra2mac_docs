### 2.3 C-02i 死因报告（只读，本轮未改一行代码）

现象：`digging=1 carrying=1 cargo=4 credits=0`，3500 拍循环跑满（`RuntimeSlaveMinerSmoke.inl:474-499`）。

**已排除两条**（这次不是靠跑读数，是靠读结构体与赋值顺序——这类排除比跑读数更便宜，只要肯读）：

1. ~~`context.credits` 不回写，钱进了临时副本~~ —
   `HouseEconomyContext::credits` 是 `int&`（`HouseEconomyContext.h:9`），直指 `state.economy.credits`，
   `runtimeCreditBalanceAfterDeposit` 写的就是真账。**假设不成立。**
2. ~~`cargoValue<=0` 被当空返，所以 cargo 满却没钱~~ —
   `task.cargoValue += value` 与 `++task.cargoUnits` 在**同一分支同步执行**（`RuntimeSessionProduction.cpp:7562-7564`），
   `value<=0` 时提前 return 且**不增** units。所以 `cargo=4` 必然伴随 `cargoValue>0`，
   永远走不到 `returned empty` 那条清账分支（`:7341`）。**假设不成立。**

**剩余候选（改法相反，不许猜）**：

- ① 交付分支的前置谓词 `runtimeSlaveMinerWorkerAtRefinery` 从未成立。它要求 `!worker.renderMoveActive`
  **且承诺格与身体格的到地基距离都 == 0**（`:7232-7247`）；而返程发的是 `findRuntimeEngineerEntryCell(..., 2)`
  返回的**地基内**格（该函数只在地基格集合里排序取点，`:20991`）。两者本该一致，
  不一致只可能是「人到了但 `renderMoveActive` 没清」或「身体格滞后一格」。
- ② 交付分支跑过、`recordRuntimeHouseResourceDelivery` 因 `resourceStorageCapacity==0` 吞掉入库。
  但 credits 在容量判断**之前**就加了，纯容量解释不成立，只可能连带把 cargo 清零后循环重来。

**还缺什么（重开条件）**：一条默认静默的读数，挂在 `advanceRuntimeSlaveMinerWorkerTask` 入口，
每 120 拍打一行 `id / phase / mission / cargo / renderMoveActive / 到地基格距离 / behavior.kind`。
**一次运行**即可裁定 ①/②。这条读数没有写——因为本轮是收口轮，按纪律不改代码；
把它写成「重开条件」而不是「明天就做」，是为了不让第 10 个子项在今天悄悄诞生。

## 6. 本轮没做什么 / 遗留什么债 / 放弃了什么

**本轮没做什么**

- 没修任何产品缺陷。C-02i 明知有两条候选、明知一条读数就能裁定，仍然只写到「重开条件」为止——
  因为再开一个子项就是第 10 个，红线已经超了两倍，先收口再谈修。
- 没把 `ledger-check.sh` 接进 `regress.sh`。误接会让「RED-NEW 条数」这个退出码语义被稀释。
- 没做 S-08 的计量（它是 M-03 的前置，但本轮时间给了清单治理）。

**遗留什么债**

- **`ledger-check.sh` 只挂在人工流程上**。规则四说「当轮第一件事是压缩归档」，靠的是每轮开头有人跑它。
  下一轮应把它接成 `regress.sh` 的**第 0 步**（只打印不判红），或写成轮次协议的第一条命令——两者选一，别再悬着。
- **`attempts` 字段历史上全是 0**。本轮只保证新条目必填，旧条目不追认。C-02 那种「拆新 ID 续命」的形态
  在旧数据里已无法度量，只能靠规则六.2 的事前约束。
- **`queue.json` 里 25 条 pending 的估值字段（`value` / `cost` / `roi`）多为空**。它们本轮不参与排序（收口轮不排序），
  但下一轮一旦要按性价比排，必须先补齐，否则排出来的顺序是假的。

**放弃了什么**

- **C-02 这条主线放弃继续推进**，剩余交付段 defer。这意味着「尤里奴隶矿工能赚钱」这个用户可观察行为
  在当前版本上是**缺的**，而且短期内不会补。这是本轮最实在的一次取舍。
- 放弃「把 9 个子项全部做成 done」的账面好看。9 个子项里 5 个是夹具/断言口径，做成 done 也不改变产品行为。
