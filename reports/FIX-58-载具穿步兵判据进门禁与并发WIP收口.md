## 二、S-24：判据为什么进不了门禁（根因）

| 层 | 状态 |
|---|---|
| 缺陷本身（M-25） | 用户实测确认的 S 级：几个步兵站一起后载具**彻底**过不去。R44/R48/R49 三次修复尝试全为负结果，主线已判 blocked（`reports/FIX-50` §四） |
| 判据 | 2026-11-14 就写好了：`RuntimeVehicleInfantryPassThroughSmoke.inl`，93 行合成夹具，只判一格 |
| 门禁 | **缺**，且不是「忘了接」——是**接不了** |

`S-24` 从第 47 轮挂 `blocked` 到第 57 轮，理由写得很清楚：「未跟踪文件接进门禁，干净树重建后
该环境变量消失 → 退回跑主档，以别的文案红出来，制造永久假 `cause-changed`」。这条判断是对的，
而它把问题锁死成一个死结：**要进门禁必须先入库，要入库得先有人替并发会话做归属判定**。

本轮做的就是把死结解开，只解开这一格：

- `782e194`（99 行）：`.inl` 入库 + `CONCORD_COMMAND_SMOKE_VEHICLE_INFANTRY_PASS_ONLY`
  分支 6 行。**不改产品行为**。
- `96ed2ee`（5 行）：失败文案加回 `failed` 三个字母。原因见下，**这是本轮唯一一处
  「看起来是形式主义、实际是判据失效」的发现**。

### 2.1 一个把门禁钉在噪声上的坑（`pick_evidence`）

`regress.sh` 的 `pick_evidence()` 按 `*failed*` / `*Smoke:*` / `*done:*` 选证据行，
**取最后一个匹配行**。本冒烟在被测数据根下会先打印：

```
Failed to open INI file: local_data/resources/mix_exports/multimd/2peaks.map
```

它含 `Failed` → 被选为证据行；而真正的失败行原本是
`vehicle pass-through infantry: vehicle refuses a cell occupied only by friendly infantry`，
**不含 failed**，于是抢不走证据位。后果：known-red 的第 4 列只能钉在那行 INI 噪声上，
**真原因换了（cause-changed）也照不出来**——正是 S-11 的教训换了个位置复现。

改法只动文案：`"vehicle pass-through failed: " + why`。判据与返回值不变。
`multiplayer` 那条 PASS 的证据行同样是这行 INI 噪声（见本轮回归输出），它不红所以无害，
但**同类冒烟只要失败行不含 failed 就会踩**。已记进 §五的债。

### 2.2 门禁现在的样子

```
vehiclepass  KNOWN-RED  0s  vehicle pass-through failed: vehicle refuses a cell occupied only by friendly infantry
                             ↳ M-25 的产品缺陷本身（不是夹具问题）… ①锁住「空地必须可走」的对照组
                               （夹具一坏先红这一支）②M-25 修好时自动转绿、前缀可注销
```

**它的价值不是「多一条绿」，而是两条**：对照组（`emptyCellPassable`）此前没有任何日常门禁，
夹具一坏（例如 `initializeRuntimeNavigation` 改动）现在会先红；以及 M-25 哪天真被修好，
这条会自己转绿，不需要谁记得去注销前缀。

## 六、操作事故（必须记，两次都是同一个原因）

本轮写 `.inl` 文案时用了 `git commit -am`，**`-a` 把工作区里 677 行并发 WIP 一并卷进了一个
「test: 文案」提交**；紧接着用 `reset --soft HEAD~1` 回退后**忘了清索引**（`--soft` 保留暂存），
于是第二个 commit 又把全部 14 个文件收了进去（1,218 行）。

两次都用 `git reset --soft HEAD~1` + `git reset`（mixed，工作区不动）纠正，**没有丢任何改动**，
也没有用 `--amend` 或 `--hard`。最终历史是 4 个各自对应一个根因的 commit。

**教训**：这台机器上 `git status` 只要不是空的，`-a` 就是一把上膛的枪；`reset --soft` 之后
必须先 `git reset`（mixed）再 `git add <路径>`。**三次修正同一批内容的代价，比一开始就逐个
`git add` 高得多**。
