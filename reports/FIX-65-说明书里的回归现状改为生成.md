# 第 65 轮（修复轮）：说明书里的「回归现状」不再由人写

> 轮型：修复轮。**按 `§六.5` 强制换赛道**——M-03 主线连续 2 轮无产品行为变化（R63 删兜底假设被推翻、
> S-08 只是计量），本轮不许再碰它，从「清偿 / 可观测性 / known-red / 打包与文档」里选。
> known-red 两条分属 C-02（9 子项）与 unit-behavior（4 子项）两条已满额的 blocked 主线，不许续命；
> 清偿轮刚从 R62 做过（KPI 已达成）。所以选**打包与文档**：主目标 **S-34**。

## 一、现象：发给用户的说明书里，回归读数是假的（已经错了两次）

`dist/README.txt` 这一段长期靠人手写：

    共 **15 条：13 绿 / 2 known-red / 0 新红**（约 35 秒）

本轮用新加的 `--check` 打在当时那份 `dist/README.txt` 上，直接照出来：

    STALE 第 123 行起不一致：
      应是: 共 **16 条：14 绿 / 2 known-red / 0 新红**（最近一次 2026-11-16 02:31，源码 `73be404`）
      实为: 共 **15 条：13 绿 / 2 known-red / 0 新红**（约 35 秒）

两次翻车的时间线：R59（S-33）手工把 14 条改对；R60 加了第 16 条 `paradropsel`，这句又错了，
而门禁一条没报——因为**没有任何东西在量这份文件**。

## 二、根因：事实的生产者与消费者之间缺一个生成步骤

- 生产者：`regress.sh`（每轮跑，结果只落在人读的 `report.md` 与终端）。
- 消费者：`packaging/README-dist.txt`（入库、被 `pack-dist.sh` 第 ⑩ 步原样 `cp` 进 `dist/`）。
- 中间：**空**。于是「改对」是记性问题，「改错」是必然事件。

S-33 的结论当时写成「根因不是忘了改，是没有任何东西量它」，但处置只做到「手工核过三处事实」——
手工核一次，下一次加门禁照错。这与本项目的 MIN_MACOS / S-37 是同一形态：**只查一次，不是门禁**。

## 三、改法（三处，都在脚本层，零产品代码）

1. **`regress.sh` 收尾多写一行机器可读汇总**：`progress/regress/latest.txt`，一行 k=v：
   `source=73be404 stamp=20261116-023401 pass=14 knownred=2 new=0 total=16 arch=arm64 built=… dirty=1`。
   人 `cat` 也读得懂，脚本按空格切；`source` 带 `+WIP` 时说明书里也会带（脏树的说明书写脏树的读数）。
2. **新增 `scripts/render-readme.py`**：按 `<!-- regress:begin -->` / `<!-- regress:end -->` 替换那一段。
   - 数据源优先 `latest.txt`，没有则回退扫最新的 `progress/regress/<时间戳>/report.md`；
   - 两处都没有 → 写「这台机器没有可用的回归产物」并返回 **3**，而不是把旧数字抄一遍；
   - `--check` 只比对不写盘（退出码 1 = 说明书与回归产物不一致），这就是给「说明书在说谎」用的显式判据；
   - 标记行在渲染结果里被删掉（`.txt` 里留 HTML 注释会让人以为是漏写的内容）。
3. **`pack-dist.sh` 第 ⑩ 步改调它**：rc=0 正常；rc=3 打一行 WARN 继续出包（说明书此刻说的是真话：
   本机没跑过回归）；其它非 0 一律 `exit 1` —— **宁可不出包，也不出一份会说谎的包**。

known-red 的**列表**（id + status）也改为从 `known-red.tsv` 生成；两条的**用户可见含义**
（「奴隶矿工不产生收入」「载具被友军步兵堵住」）仍是人写的，单独成段并写明
「条目转绿后本段请顺手删」——它描述行为，没有廉价判据，不假装机器能判。

## 四、负向验证（先红后绿，都是可复现命令）

| 验证 | 做法 | 结果 |
|---|---|---|
| 条数跟着数据走 | `known-red.tsv` 追加一行 + `latest.txt` 改成 19/15/3/1 | 渲染出「共 19 条：15 绿 / 3 known-red / 1 新红」+ 第三条 bullet |
| 没数据不抄旧数字 | `--base` 指向空目录 | 输出「本机没有可用的回归产物」，rc=3 |
| 假话能被抓 | `--check` 打在打包前的 `dist/README.txt` 上 | 第 123 行 STALE，rc=1（见 §一） |
| 真话能被认 | `--check` 打在刚打包的 `dist/README.txt` 上 | 打包后复跑，`ok readme-regress` |

## 五、本轮没做什么 / 遗留什么债 / 放弃了什么

**没做什么**
- 没碰任何 C++（本轮产品代码净增 0）；M-03 按 `§六.5` 换赛道，一条没动。
- 没做 `ledger-check.sh` 的第 14 项门禁（「`dist/README.txt` 与最近一次回归不一致」）。
  理由：每轮中途跑完回归、打包在收口，这条在时间上必然有 20 分钟的「合法窗口」里是红的，
  会变成恒真噪声（与 R64 修掉的 `build-health` 分母同一个坑）。判据先做成 `--check` 可用，
  什么时候该进门禁等审计轮定。
- 没动 README 里「数据根搜索顺序」那段——它仍是人读 `RuntimeConfigPaths.cpp` 对照，已写进文件尾。

**遗留的债**
- 说明书里还有一批**没有廉价判据**的描述性事实（全屏语义、指针捕获、Gatekeeper、重新打包顺序）。
  它们只能靠 review，本轮只把「机器能验」的那一处拿掉了。
- `latest.txt` 目前只有一个消费者（说明书）。若将来 `BUILD-STAMP` 的 `regress=` 也改从它读，
  两个产物就只有一个事实源——本轮没做，因为 BUILD-STAMP 的字段比它多（minos/icon/rosetta）。

**收口时新发现的（当场没修，已登记）**
- 打包收尾实测：**`dist/BUILD-STAMP.txt` 仍是人手写的一行**，pack-dist 不写它。本轮打完包时那份文件还停在
  上一轮的 `73be404 … round=R64`，直到手工覆盖才与 HEAD 一致——而它正是「dist 是不是最新」的唯一判据。
  与 S-34 完全同一形态（可验证事实靠人写），登记 **S-38**（thread=交付），本轮不动手：时间已到锚点。
  这也说明本轮的结论没有走到尽头：**说明书修好了，旁边那个更关键的戳还是人写的**。

**放弃了什么**
- 放弃「在本轮顺手把 `dist/README.txt` 的回归段做成 `make-dmg.sh` 的挂载后门禁」：
  dmg 拷的是 `dist/README.txt`（已经是生成物），验它等于验同一份文件的复印件，性价比不够。
