# M-25 载具被友军步兵挡死：根因确认 + 一个不能上线的改法

日期：2026-11-14 07:4x
状态：**根因已确认，修复未落地**（判据已留，当前红灯）

## 1. 用户口径

> 坐下了几个大兵，明明感觉有空间，其他的兵种就走不过去

追问澄清：这是**缺陷**，且是**彻底堵死**（不是走得很慢）。

## 2. 判据（先立，当前红）

新 smoke：`src/simulation/navigation/occupancy/diagnostics/RuntimeVehicleInfantryPassThroughSmoke.inl`
入口：`CONCORD_COMMAND_SMOKE_VEHICLE_INFANTRY_PASS_ONLY=1 <bin> --command-smoke-test`

```
vehicle pass-through: emptyCell=1 friendlyInfantryCell=0
vehicle pass-through infantry: vehicle refuses a cell occupied only by friendly infantry
```

`emptyCell=1` 是对照组（空地可走，证明夹具没坏），`friendlyInfantryCell=0` 是缺陷本身。

**为什么用格子级判据而不是"路径规划成功"**：路径层会绕路，绕过一圈 smoke 就绿了，
而用户看到的正是「绕不过去」的那一刻。只有格子级读数能分开「能过 / 绕路 / 堵死」。

## 3. 根因

载具 mover 落到 `RuntimeSessionNavigation.cpp` 通行判定的最后一支：

```cpp
} else if (!runtimeCanEnterAndCrushCell(state, mover, occupiedCell, ...)) {
    passable = false;
}
```

`runtimeCanEnterAndCrushCell` 对同阵营目标恒 false（不压友军），于是
**"友军步兵挡路" 在寻路层等价于 "一堵墙"**。1 格宽的走廊一旦有人站着，路径直接为空。

对照：步兵 mover 不受影响——它有 `infantryHasSubcell` 分支（格内 3 个子格还剩就放行）。
所以现场表现是「步兵能挤过去，载具过不去」，和用户描述的"其他兵种"完全对得上。

## 4. 试过的改法（已回退）

### 改法：只放行「格内占据者全是友军步兵」的格子

新增 `runtimeCellGroundOccupantsAreOnlyFriendlyInfantry`（逐个数占据者，不信任
representative occupant 那一个 id），在**三个入口**统一调用：

1. 寻路快照的 passable 循环（`RuntimeSessionNavigation.cpp` 5140 附近）
2. `runtimeCellIsPassableUncached` 的 exact-miss 分支
3. `runtimeCellIsPassableUncached` 的主 occupied 分支

三个入口必须同一个判据，否则表现会是「寻路能过、提交时判死」。

### 结果：判据转绿，但引入了一个真回归

| smoke | 基线（未改） | 放行后 |
|---|---|---|
| `vehicle pass-through`（新） | 🔴 `friendlyInfantryCell=0` | 🟢 `=1` |
| `12E1_2MTNK_tank_first`（12 步兵 + 2 坦克同目标） | 🟢 PASS，1870 拍收敛 | 🔴 `arrival_timeout; ground_final_not_compact` |
| `12E1_2MTNK_foot_first` | 🟢 PASS，2337 拍 | 🟢 PASS |
| `3MTNK_3SHAD` | 🔴 `ground_final_not_compact`（既有） | 🔴 `arrival_timeout`（失败文案变了） |
| `regress.sh` 全量 | 10 PASS / 1 KNOWN-RED | 10 PASS / 1 KNOWN-RED（**这条没覆盖到**） |

**关键教训**：`regress.sh` 全绿**不能**证明这个改动是安全的——它不跑
`CONCORD_COMMAND_SMOKE_COMPACT_GROUPS_ONLY`。混合编队收敛这条路径只有那个 smoke 在线。

### 为什么放行会破坏编队收敛

放行之后载具真的会开进步兵格，但**没有任何东西把步兵挪开**：

- 载具占了整格 → 步兵进不来（子格被硬阻挡）
- 步兵不让位 → 两人互相顶住，群体目标分配无法收敛
- `tank_first` 场景（坦克先动）正好命中这条：坦克先插进去，步兵被挡在外面

也就是说，**"允许通过" 只是解除了寻路的否决权，运动层并没有对应的挤压能力**。
半截修复比不修更糟——从"过不去"变成"卡成一团且不收敛"。

## 5. 正确的修法（下一步）

缺的是**挤压（displacement）**，不是通行判定：

1. 载具 commit 进入某格前，若该格有友军步兵，把这些步兵挪到最近的空闲子格/相邻格；
2. 或者按原版做行为层：载具因友军阻塞停滞 ≥ K 拍时，给前方扇形内的友军 Idle 步兵
   下达一次短距离 Move。

两条路都要动运动层，风险与工作量都不小，且必须有 `12E1_2MTNK_tank_first` 这种
混合编队 smoke 作为验收（只跑 regress.sh 会漏）。

**顺序建议**：先做 1（一次性挤压，几何清晰、可断言"进入后无重叠"），
再考虑 2（行为层让路，手感更好但更容易误伤玩家指令）。
