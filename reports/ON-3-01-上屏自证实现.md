# ON-3-01 上屏自证：贴上去的那张图，和渲染出来的那一帧是同一张吗

> 2026-11-11 07:00–07:35 · 人工接续轮（持 `.active` 独占锁）· 源码提交 `1001196`
> 队列：`ON-3-01`（done）、新增 `ON-3-01b`（五界面扩展，等 ON-4-02）

## 一、为什么这条必须先做

ON-2-05 的教训是「present 被调用 ≠ 屏幕上有画」：主窗口先于主菜单子窗口 EndPaint，
抢到呈现位、贴了一张全 0 的帧，所有日志正常、屏幕全黑。修完之后也没有任何**自动**
证据能证明「layer 上那张图 == 这一帧渲染结果」——只有一张人工截图。

ON-3-01 要补的就是这一层：把 `layer.contents` 里的 CGImage 读回来、重画成位图，
与同一帧 DIB 逐像素对账。它证明的是「贴上去的对象就是这个渲染帧」，不证明「显示器
真的亮了」（后者要人眼或窗口抓图，属 ON-3-02/03）。两层证据必须分开记。

## 二、三次被实测推翻的直觉

### 1. 不能借既有 smoke 驱动：它们全是离屏的

第一版把 `--onscreen-attest-smoke` 实现成"依次跑 main-menu / skirmish / interaction
三条 smoke"，结果 `records=0`。查日志：**三条 smoke 里没有一行 `[cocoa] NSWindow created`**，
`present()` 一次都没被调用——它们只画到 DIB、导 BMP。`runRuntimeMainMenuSmokeTest` 的
注释其实写了 "without creating a window"，是我没先读。

> 取证只能挂在**真实启动**路径上：`runRuntimeWindowWithMultiplayerFailureRecovery`。

### 2. hash 对不上不是"贴错了"，是重绘时多翻了 y

第一版把 CGImage 画进 `CGBitmapContext` 前做了 CTM 翻转（以为 CG 用户空间 y 向上，
不翻会上下颠倒），结果：

```
layerHash=0x791959b8  dibHash=0x175b3678   match=no
```

把三条 hash 同时打出来就一目了然：

| 取法 | hash | 判定 |
|---|---|---|
| 翻转后重绘 | `0x890043ac` | 差 |
| **不翻转重绘** | `0x674d476c` | **等于 dibHash** |
| 直接读 CGImage provider 数据 | `0x674d476c` | **等于 dibHash** |

CGImage 的数据第 0 行就是图像顶行，`DrawImage` 到 `(0,0,w,h)` 时 GC 把顶行对齐到
rect 顶部，而 `CGBitmapContext` 的缓冲第 0 行正是顶行——**本来就对齐，翻转反而颠倒**。
（与 `rules.cg_bitmap_row_zero_is_top` 不冲突：那条说的是"按底行解释缓冲会得到翻转的
字形"，这里是"画进缓冲时不要额外翻转"。）

正式实现固定不翻转，并保留 `providerHash` 作交叉证据：两者不等时能立刻分辨是
"重绘解释错"还是"贴的根本不是这帧"。

### 3. 拿够帧数后要能自己退出，而两条常规退出路径都不通

- `CONCORD_QUIT_SELFTEST`（合成 Cmd+Q）：主菜单能退，**世界视图不能**——那里的窗口
  不是 key window，键等价物收不到，进程继续跑，只能外部 kill。
- `[NSApp terminate:nil]`：本项目从不跑 `[NSApp run]`，terminate 依赖的事件循环不存在，
  它只是把请求排队；在 `pumpEvents` 里发也无效（世界主循环根本不经过那条路径，实测
  首帧之后 `pumpEvents` 不再被调用）。

最终在 `present` 里写完记录就 `std::_Exit(failures == 0 ? 0 : 1)`：不依赖任何循环，
不跑 static 析构（避开 `rules.handle_table_outlives_process` 那类退出期 SIGABRT），
日志先 `fflush`，退出码带上失败数——**不能用 `_Exit(0)`，那会把 `match=no` 掩盖成成功**。

开关与约定：

```
CONCORD_ONSCREEN_ATTEST_DIR=<dir>      开启，逐条追加 <dir>/onscreen-attest.log
CONCORD_ONSCREEN_ATTEST_LIMIT=<n>      拿够 n 帧后 _Exit（默认 1）
--onscreen-attest-smoke <dir>          等价于"真实启动 + 设上面两个环境变量"
```

日志每行一条，字段即判据：

```
idx=1 size=1024x640 title="" layerHash=0x226d4280 dibHash=0x226d4280 providerHash=0x226d4280
      match=yes visible=1 key=0 scale=2.0 frame=1024x672 layerContents=set
```

只比 B,G,R 三个字节：32bpp BI_RGB 的第 4 字节不是 alpha（S14b 刚教过），
GDI 保留目标原值、CGImage 用 NoneSkipFirst 跳过它，拿它参与 hash 会得到一条永远红的假断言。

## 五、覆盖范围：5 个界面里 2 个要等 ON-4-02

原 verify 要求"五个界面各一条：主菜单 / 单人页 / 遭遇战大厅 / 加载 / 游戏内"。
本轮可自动覆盖 3 档（主菜单、800x600 壳、指针导航窗口），但：

- **遭遇战大厅 / 加载页**：`--skirmish-ui-smoke-test` 是离屏的，present 0 次；
  要走真实呈现必须在真实窗口里用鼠标点进大厅，即 ON-4-02 的合成输入。
- **单人页**：指针导航确实会切页，但切页渲染不再触发 present（多次 present 只发生在
  尺寸变化时），所以只留下一条记录。

所以把"五界面"拆成 `ON-3-01b`（依赖 ON-4-02），`ON-3-01` 的 verify 收窄为
"机制 + 可自动覆盖的档位，逐条 match=yes"。这不是放宽标准：机制本身已经能证明
任意一次 present 的贴图正确性，缺的只是**驱动到那几个界面的手段**。

## 六、教训（已写进 queue rules）

1. **既有 smoke 是离屏的**。凡是要证明"屏幕上"的事，先确认 `present` 有没有被调用
   （看 `[cocoa] NSWindow created`），否则会在离屏 BMP 上做一堆无效断言。
2. **画进 CGBitmapContext 不要翻转 CTM**。CGImage 顶行对齐 rect 顶部，缓冲区第 0 行
   也是顶行；翻转是 S4-2 那个"字形上下颠倒"陷阱的镜像版本。
3. **取证退出必须发生在 present 内**，且退出码要带失败数。世界主循环不走
   `pumpEvents`，`NSApp terminate` 在没有 `[NSApp run]` 的进程里只排队不生效。
4. **同一条记录里放三条 hash**（重绘 / provider / DIB）。对账失败时，三者一比就知道
   是解释错还是贴错帧；只放一个 `match=no` 会逼下一轮重新二分。
