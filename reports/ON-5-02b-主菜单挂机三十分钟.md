# ON-5-02b 主菜单挂机 30 分钟（存活台架）

> 轮次：第 71 轮（2026-11-16，台架轮）。队列首条。**只做菜单档**，世界档拆 `ON-5-02c`。
> 命令：`CONCORD_PRESENT_STATS=1 CONCORD_PRESENT_STATS_UNTIL_SEC=1800 /usr/bin/time -l \
> dist/尤里红警.app/Contents/MacOS/concord_runtime`（包内二进制，universal，未加任何 `--skip`）

## 一、为什么这条台架必须跑

S-18（第 28b 轮）的 37 GB 全漏在**菜单动画路径**上：`pumpEvents` 每轮调
`syncGlobalCursorForPointer()` 在 `@autoreleasepool` 外面，`[NSCursor currentSystemCursor]`
与 `[NSWindow windowNumberAtPoint:]` 产生的临时对象在「从不跑 `[NSApp run]`、根 pool 永不 drain」
的前提下只增不减。修法是 `505024d`（把它移进 pool）。

此后只跑过**世界视图 10 分钟**（ON-5-02a，RSS 341→342 MiB），菜单这条路径**从未进过台架**——
而它正是当年出事的那条。台架的判据不是「现在没崩」，是「修完之后它在长时间尺度上还平不平」。

|---|---|---|
| 退出 | 到点 `_Exit` | **EXIT=0** |
| paints | 134（13.39/s） | **23436（13.02/s）** |
| attempts / blank | 136 / 2 | **23438 / 2** |
| redundant / takeover | 0 / 0 | **0 / 0**（`{self=0 other=0}`） |
| user CPU | 1.39 s | **204.36 s = 11.4%** |
| sys CPU | 0.47 s | 52.92 s = 2.9% |
| `maximum resident set size` | 314.0 MiB | **352.9 MiB** |
| **`Physical footprint` 峰值** | **157.65 MiB** | **157.66 MiB（+16 KB）** |

`Physical footprint` 逐点采样（`vmmap -summary <pid>`，每 45 s，24 个点）：

```
12:06:27 119.3M   12:08:00 119.4M   12:15:44 119.3M   12:26:33 119.3M
12:07:14 119.4M   12:08:46 119.4M   12:25:46 134.3M   12:28:06 119.3M
```

**24 分钟内恒定 119.3 M，唯一一次 134.3 M 在 12:25:46 出现、下一采样点即回落到 119.3 M**
（非单调、有界，属一次分配尖峰而非累积）。峰值 157.66 MiB 与 10 秒短跑的 157.65 MiB
只差 16 KB —— **这条路径上 30 分钟没有可见泄漏**。

## 三、两个口径差 38.9 MiB，按哪个判

`maxRSS` 314→353 MiB（+38.9 MiB），`footprint` 峰值只 +16 KB。**按 footprint 判**：

- `maxRSS` 是高水位线，含可回收页（file-backed、尚未触碰的脏页）；10 秒跑里启动期就已顶到
  314 MiB，所以「30 分钟比 10 秒多 38.9 MiB」里绝大部分不是这 30 分钟长出来的。
- `Physical footprint` 是实际占用。本项目判泄漏的口径一直是它 + `DefaultMallocZone` 分配计数
  （见 `reports/FIX-30-挂机内存泄漏-autoreleasepool.md`）。

**必须写清这条**，否则下一轮看到「30 分钟 RSS 涨了 39 MB」会当成回归，再白查一次。

## 四、顺手照出来的两件事（未定性，别当结论）

1. **主菜单的 Bink 是首帧静止画**。日志：
   `Main menu Bink animation unavailable: Bink playback is unsupported on this platform;
   using the original extracted first frame.`
   → 所以 ON-5-02b 原本设想的「Bink 首帧 + 告警灯动画」里，**Bink 那半边在本平台根本没动**。
   这条台架覆盖的是「静态主菜单 + 光标收敛器每帧跑」这条路径，不是「视频在放」那条。
   要覆盖后者得先有 Bink 后端（未做）。
2. **静态主菜单仍有 13.02 paints/s**。1800 秒里 paints 涨了 23436，与 attempts 只差 2（=启动时
   的 blank），`redundant=0`。画面在 30 分钟内没有用户可见变化，却稳定 13 次/秒提交 ——
   与 ON-2-06 / M-03「世界 idle 33 次/秒」是**同族但另一条路径**。本轮不猜来源
   （光标收敛器、文本层重建都可能），只记数：**它不是泄漏源，但它花了 11.4% 的 CPU 去画一张不动的图。**

## 六、代价与未做

- 本轮**没有改任何代码**，所以没有重新构建、没有重跑回归、dist 保持 `ac45ada`（与 HEAD 一致）。
- 台架占用约 30 分钟墙钟；期间**刻意不跑构建与 regress**——这条台架测的就是 CPU 与 RSS，
  并发负载会直接污染读数（这是 §一 那条「当年漏了 37 GB」唯一能复现的地方，读数脏了整轮白跑）。
- 世界档 1800 秒留 `ON-5-02c`：世界路径是 60 fps、CPU 16.5%（R68 实测），与菜单的 13 fps / 11.4%
  不是同一条曲线，不能拿菜单档的结论外推。
