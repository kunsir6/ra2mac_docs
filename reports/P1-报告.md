> 完成时间：2026-11-10
> 目标：让「Windows 与 macOS 并存」在**构建系统层面**成立，且可自证 Windows 侧零回归。
> 结论：**达成。** Windows 分支逐字节未动，macOS 侧多出一条独立分支。

## 一、改了什么

只动了两个文件，一个是新增，一个是新增 16 行。

| 文件 | 性质 | 行数变化 |
|---|---|---|
| `cmake/PlatformApple.cmake` | 新增 | +119（新文件） |
| `cmake/CompilerAndPlatform.cmake` | 纯追加 | **+16 / −0** |

### 1. 新增 `cmake/PlatformApple.cmake`

这是 macOS 平台轴的唯一入口，四条能力开关 + 三个工具函数。

**能力开关**（全部默认保守值）：

| 开关 | 默认 | 含义 |
|---|---|---|
| `CONCORD_APPLE_SDL3_WINDOW` | **OFF** | SDL3 窗口后端（P3 才实现） |
| `CONCORD_APPLE_SDL3_AUDIO` | **OFF** | SDL3 音频后端（P4 才实现） |
| `CONCORD_APPLE_SOFTWARE_PRESENT` | **ON** | CPU 软件帧呈现，无 GPU 依赖 |
| `CONCORD_APPLE_METAL_PRESENT` | **OFF** | Metal 呈现 |

默认值的方向是刻意选的：**未实现的后端一律 OFF**。如果留 ON，后果是链接期崩溃——离病因很远；留 OFF 则是在调用点报一句清楚的话。

**工具函数**：

- `concord_apple_strip_win32_sources(<list-var>)` — 用一个正则把 `/win32/` 实现从源列表里剔除。因为这个项目的源文件全是显式列出、且 Win32 实现一律放在 `win32/` 目录下，所以一条规则就够，不用在每个源列表旁边撒 `if(APPLE)`。
- `concord_apple_link_frameworks(<target> <framework>...)` — 框架名由调用方显式给出，模块本身不猜依赖。
- `concord_apple_assert_no_win32_sources(<target>)` — **configure 期守卫**，Win32 翻译单元若渗进 Apple 构建就直接报错。

第三条的价值在于换了一种失败方式：泄漏的 win32 TU 原本表现为 `windows.h` 找不到，读起来像编译器问题；守卫让它表现为「构建图有问题」，指向真正的原因。

### 2. `cmake/CompilerAndPlatform.cmake` 追加 16 行

两个位置，都是插入：

```
位置一（PORTABLE_CORE 早退块之后）：
    if(APPLE)
        include("${CMAKE_CURRENT_LIST_DIR}/PlatformApple.cmake")
    endif()

位置二（既有 if(WIN32) 链接块末尾，追加 elseif）：
    elseif(APPLE)
        message(STATUS "concord_apple: sdl3-window=... software-present=...")
    endif()
```

`CompilerAndPlatform.cmake` 之所以是正确位置：它是 `CMakeLists.txt` 第 25 行、在 `GameTargets.cmake`（第 22 行）之后 include 的**唯一尾部钩子**，此刻所有目标都已创建，`target_*` 调用才有效。

## 三、轴分离确实生效

`compiler-contract-Release.txt` 的实际内容（产品级与内核级一致）：

```
OS=Darwin
compiler_id=AppleClang
compiler_version=21.0.0.21000101
frontend=GNU
Microsoft_ABI=OFF
CPU_ISA=x86_64
```

`Microsoft_ABI=OFF` 这一项是关键：它让 `CompilerAndPlatform.cmake` 里那一大段 `if(CONCORD_MSVC_FRONTEND)` 里的 **80 多个 `/utf-8 /FS /W4 /WX` 配置全部自动跳过**，一行都不用改。

这正是作者在 `CompilerContract.cmake` 里声明「OS / frontend / ABI / CPU ISA / 窗口后端是彼此独立的轴」带来的红利。

## 四、一个认知修正

我最初以为 win32 源是靠「列表过滤」排除的，所以要写个强力的 strip 逻辑。

读了 40 多个 cmake 文件后发现实际机制不同：win32 实现是**逐个通过 `concord_add_profiled_leaf(...)` 写在 `if(WIN32)` 里**的。所以才只有 4 个进了产品编译图——其余都是因为那个 target 在 macOS 上压根没被创建。

含义：**真正的机制是守卫，strip 函数只是兜底**（用于将来某些共享列表里混进 win32 源的情况）。P2 的工作重心因此不是「过滤构建图」，而是「为这 4 个 TU 提供替代实现或让它们退出构建」。

## 五、Windows 零回归怎么自证（给人看的方法）

三条，从弱到强：

1. `git diff --numstat` 删除列为 0
2. `if (WIN32)` 块与 `HEAD` 逐字节一致（本次已验证 1559 字节全等）
3. **最终凭据**：Windows 侧 `compiler-contract-Release.txt` 与 `baseline/core-windows-x64.json` 对比（待 **B-01** 由用户在 Windows 机器产出）

第 3 条才是真正的事后对账凭据。前两条只能证明「我这次没碰」，第三条能证明「碰完之后行为没变」。所以 B-01 虽不阻塞推进，但**必须在首次提交前补齐**。
