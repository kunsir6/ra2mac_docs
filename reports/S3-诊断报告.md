| 归属 | 数量 | 证据 |
|---|---|---|
| **S3** GDI 矢量 + DC 状态 | **42** | 只在绘制上下文出现，不碰 HWND |
| **S7** 窗口/消息 | 14 | `GetDC/ReleaseDC/GetClientRect/ClientToScreen/ScreenToClient/GetWindowRect/GetWindow/WindowFromPoint/InvalidateRect/ValidateRect/RedrawWindow/GetUpdateRect/GetWindowLongPtrW/SetWindowLongPtrW` |

队列里写的「约 40 个」是对的，现在变成精确值：**42**。

## 2. 本轮最重要的发现：DC 查询函数是承重的

项目里存在三条「快路径」，它们**先校验 DC 状态，再直接写 DIB 像素**，绕过 GDI 图元调用：

- `src/ui/selection/RuntimeSelectedPathRaster.h:202` `supported()`
- `src/ui/selection/RuntimeSelectionFrameRaster.h:157` 构造函数
- `src/ui/selection/RuntimeSelectionFrameRaster.h:176` `beginTrustedRestoredDcStateBatch()`

`supported()` 要求下列**全部精确匹配**，任何一项不符就返回 false：

| 查询 | 期望值 | Win32 默认值 |
|---|---|---|
| `GetBkMode` | `TRANSPARENT`(1) | OPAQUE(2) ← 调用方显式设置 |
| `GetROP2` | `R2_COPYPEN`(13) | 13 |
| `GetGraphicsMode` | `GM_COMPATIBLE`(1) | 1 |
| `GetMapMode` | `MM_TEXT`(1) | 1 |
| `GetArcDirection` | `AD_COUNTERCLOCKWISE`(2) | 2 |
| `GetLayout` | `0` | `LAYOUT_LTR`(0) |
| `GetCurrentObject(dc, OBJ_BRUSH)` | `== GetStockObject(NULL_BRUSH)` | NULL_BRUSH |
| `GetWindowOrgEx` / `GetViewportOrgEx` | 返回 TRUE 且均为 (0,0) | TRUE, (0,0) |
| `GetObject(bitmap, sizeof(DIBSECTION), &dib)` | `== sizeof(DIBSECTION)`，且 `bmBits==pixels`、`bmBitsPixel==32`、`bmPlanes==1`、`bmWidthBytes==width*4` | — |
| `GetClipBox` | `SIMPLEREGION`(2) 或 `NULLREGION`(1)，并填 clip | NULLREGION 初始 |

两个推论，都很硬：

1. **「返回 0 当默认值」是错的**。`AD_COUNTERCLOCKWISE` 是 2、`SIMPLEREGION` 是 2、`GM_COMPATIBLE` 是 1——
   随手 `return 0` 会让 `GetArcDirection` 这一项永不成立，快路径永远关闭。**关闭不是崩溃，是静默降级**：
   所有 raster 契约会退化成「只跑 reference 路径」，看起来还在跑，实际什么都没验证。
2. **`GetObjectW` 是唯一的硬门槛**。它没实现，三条快路径全部 `available()==false`。而
   `RuntimeSelectedPathRasterContract.inl:90` 直接断言：
   ```cpp
   if (!raster.available()) return fail("default DIB path unavailable");
   ```
   即这条契约在 macOS 上**现在就是红的**，而且红的原因跟光栅算法一点关系都没有——纯粹是 `GetObjectW` 缺失。

### 未决语义：top-down DIB 的 `bmHeight` 正负

`RuntimeSelectedPathRaster.h:219` 的注释写着「GetObject normalizes DIBSECTION's height to positive even for
a top-down DIB」，随后按 `dib.dsBm.bmHeight != height`（height>0）比较。
按 Windows SDK 文档，`dsBm.bmHeight` 应取自 `biHeight`，top-down 时是负数。二者冲突。
但**项目这条注释是在 Windows 上跑通过的实现依据**（否则 line 90 的断言在 Windows 上就该红）。
决定：shim 先按 `abs(biHeight)` 实现（迁就项目实测语义），同时在 selftest 里钉一条断言把这个选择固定下来，
并标注「与文档不一致，需在能上 Windows 时复核」。不要在没复核前把注释当真理到处传播。

## 3. S3 的验证天花板（必须先说清，否则会误判 done）

现有 raster 契约全是**「optimized 路径 vs reference 路径」自洽比较**：两边都跑在同一套 GDI 上。

```cpp
// RuntimeSelectionFrameRasterContract.inl:60
original(reference.dc, r, c);      // 参考：走 LineTo/FillRect
if (raster.draw(r, c)) ++stamps;   // 被测：直接写像素
else { original(optimized.dc, r, c); ++fallbacks; }
GdiFlush();
if (!std::equal(reference.pixels, reference.pixels + count, optimized.pixels)) return fail(...);
```

**这只能证明「快路径与慢路径一致」，不能证明「与 Windows GDI 一致」。**
若 `LineTo` 的 Bresenham 差一像素、`FillRect` 把右下边界画成闭区间，这些契约**照样全绿**。

因此 S3 的验收必须分两层：

- **层 1（自洽）**：现有契约——证明快路径与 GDI 调用路径等价。这层 mac 上能跑。
- **层 2（保真）**：新建 `compat/win32/selftest/CompatGdiRasterSemantics.cpp`，用**硬编码期望像素**
  钉住 GDI 的边界约定：`FillRect` 右下开区间、`Rectangle` 画到 `right-1/bottom-1`、`LineTo` **不画终点**、
  `MoveToEx` 更新当前位置、裁剪取交集、`R2_XORPEN` 的 32 位 XOR 保持高字节不变（与 S2 的 DSTINVERT 约定一致）。
  这层的期望值来自文档推导，不是来自我们自己的实现——否则就是循环论证。

B-01 的 Windows 基线只覆盖 core 目标，**没有任何产品级像素金标准**，所以层 2 无法在 Windows 侧自动对拍，
只能靠文档语义 + 人工复核。这一点必须写进 S3 的 done 判据，不能含糊过去。

## 4. 建议的三轮切法

| 轮次 | 内容 | 可验证的产出 |
|---|---|---|
| S3-1 | A 段 25 个（重点：`GetObjectW` 填 `BITMAP`/`DIBSECTION`/`LOGPEN`/`LOGBRUSH`，`GetClipBox`，`GetCurrentObject`，`GetObjectType`，`GdiFlush`，`MulDiv`） | 三条快路径 `available()==true`；`RuntimeSelectedPathRasterContract` 的 line 90 从 fail 变 pass；`CompatGdiRasterSemantics` 的 DC 状态部分断言全过 |
| S3-2 | B 段 5 个（region：矩形 + 多边形，`RGN_OR`/`RGN_DIFF`，`SelectClipRgn(nullptr)`） | 裁剪相关契约（46+36 处调用点）跑通；`GetClipBox` 的 `SIMPLEREGION`/`NULLREGION`/`COMPLEXREGION` 三态有断言 |
| S3-3 | C 段 12 个（`MoveToEx`/`LineTo` 光栅器 + `FillRect`/`FrameRect`/`Rectangle` 边界规则 + 多边形 + `GdiAlphaBlend`） | 层 2 硬编码像素断言；`Ellipse`/`RoundRect` 可用「中点圆 + 扫掠」实现但必须确定性 |

顺序不能颠倒：C 段单独做出来的光栅器没有观测点（快路径还关着，契约还在 line 90 就红了）。

`GdiAlphaBlend`（`RuntimeShell.cpp:23552`，真实路径）需要预乘 alpha 约定与 S2 的 DIB 约定对齐，
否则半透明覆盖整片发黑——S3-3 里单独留一个用例。
