# U-06 世界侧栏指针消失：视口外一律不给游标帧

日期：2026-11-11 18:30

## 症状

用户实测（1024×640，遭遇战世界）：

> 在游戏页面，鼠标在地图区域可以显示，到了右边的菜单栏又不显示了。
> 预期是在各个区域，显示该显示的内容。

截图证实：光标在地图区（x≈855）是游戏自绘的箭头；移进右侧栏（x>890）后完全消失。

## 根因

`runtimeMouseCursorFrameForPoint()` 开头就把「不在视口」当成「没有指针」：

```cpp
const RECT viewport = runtimeMapViewport(clientRect);
if (!state.mouseClientPointValid || !pointInRectInclusive(viewport, point)) {
    return std::nullopt;   // ← 侧栏也走这里
}
```

`drawRuntimeMouseCursorOverlay()` 拿到 `nullopt` 就直接 return，什么都不画。
在 Windows 上这个缺陷看不见——系统箭头还在，玩家以为箭头是游戏画的；但 U-04/U-05 定案后
macOS 侧系统指针被整体隐藏，于是「地图里有、侧栏里没有」。

也就是说：**这不是新引入的 bug，是 U-05 隐藏系统指针后暴露出来的既有缺陷**。
它同时说明 U-05 的那句「产品自绘指针覆盖全窗口」其实是假设，没有验证过 HUD 区域。

## 修法

视口外不再返回空，而是回落成标准箭头（`mouse` atlas 第 0 帧，与菜单/框选时同一个箭头）：

```cpp
if (!state.mouseClientPointValid) return std::nullopt;
if (!pointInRectInclusive(viewport, point)) {
    if (!pointInRectInclusive(clientRect, point)) return std::nullopt; // 真的在窗口外
    return RuntimeMouseCursorFrame{0, 0, 0};                            // 侧栏/顶栏：原版自绘箭头
}
```

三点说明：

1. **这是平台无关的正确改进**，不是 `if(APPLE)` 补丁。原版在 Windows 上侧栏也是游戏自绘箭头，
   只是被系统箭头遮住了没人发现；改完两边语义一致。
2. 点在客户区之外仍返回空——拖到窗口外应由窗口系统接手，不该画。
3. `playerCommunication.diplomacyOpen` 的早退保留在外层，原生页面仍然不画地图指针。

## 验证

1. **新增断言**（interaction smoke，放在右取消之后、修理光标之前，因此一定会执行）：

   ```
   HUD cursor: right=1016 top=8 frame=0 atlas=mouse
   ```

   探针点取 `clientRect.right-8, top+8`，并断言它落在视口之外（防止将来视口变大后断言变成空转）。

2. **全量回归**（11 条）：`PASS=5 KNOWN-RED=6 RED-NEW=0`，与修前逐条相同；
   菜单 `rampPixels=1056,781,1428` 不变，skirmish 161 预览、attest 6 条 match 均不变。
   interaction 仍在既知的「no owned structure for repair cursor」停下（EVO-10 的事），
   说明新断言通过后才走到老缺口。

3. **产物**：`dist/ConcordRTS-0.1.0-arm64.app` 18:28 重新打包；用包内二进制跑同一条断言同样输出，
   旧包改名 `*.app.stale`（按 rules.stale_app_bundle_trap 的约定，避免又有人点到旧包）。

## 遗留风险

- 侧栏里不同控件在原版有各自的指针（雷达区可能有手形），本轮统一给标准箭头。
  如果后续发现某处应有专用指针，应在 `runtimeMouseCursorFrameForPoint` 里按 HUD 命中区细分，
  而不是回到「隐藏系统指针」。
- 菜单/遭遇战窗口是独立路径，本轮未改；它们的自绘指针此前已验证正常。
