# U-10 系统指针：移出窗口就看不见了

日期：2026-11-11 20:55

## 症状

用户：

> 当鼠标在 app 框内的时候，隐藏了系统图标。鼠标移出去就看不到了。
> ……这里也可以参考 vmware 的设计。游戏 focus 状态的时候，游戏指针不能移出屏幕……

第一条是缺陷，第二条（指针捕获）是交互设计建议，分开说。本文只写缺陷这一条，
设计评估见文末。

## 根因：一句"全局设置"被当成了"区域设置"

`RuntimeAppleWindowSurface.mm` 里 U-05 补的这段：

```cpp
// U-05：每个输入事件都重新压一次不可见光标。
if (gSystemCursorHidden) {
    NSCursor* hiddenCursor = concordInvisibleCursor();
    if (hiddenCursor != nil) [hiddenCursor set];
}
```

`-[NSCursor set]` 是**全局**的"当前游标"——谁最后 set 谁说了算，**不会**因为指针
离开窗口而自动撤销。于是指针一移出游戏窗口，WindowServer 继续把那张 1×1 空图画在
别的应用/桌面上，用户看到的就是"鼠标出去了，但啥也看不见"。

U-04 的注释写得很清楚「用 cursor rect 而不是 [NSCursor hide]/unhide，cursor rect 由
窗口按区域管理」——**但那条前提在本项目里不成立**，见下。

## 顺带查清：cursor rect 从来没生效过

一次性探针 `/tmp/keyprobe.m`：同一个窗口、同一个 `addCursorRect`，只改一件事——
事件是"只出队"还是"出队后 `[NSApp sendEvent:]`"：

| 事件处理 | NSApp.isActive | window.isKeyWindow | 指针在窗口内时的系统游标 |
|---|---|---|---|
| 只出队（本项目现状） | 0 | 0 | **28×40 箭头**（没生效） |
| 出队 + sendEvent | 1 | 1 | **1×1 空图**（生效） |

本项目从不调 `[NSApp sendEvent:]`（主循环是 compat 自己的 `GetMessageW`），于是：

1. `resetCursorRects` 里的 `addCursorRect` 是**死代码**，一直在跑、从来没起作用；
2. `NSApp.isActive` / `window.isKeyWindow` 在进程里恒为 0（除非走 LaunchServices 激活，
   那条路径上会变 1，见验证一节）；
3. 真正在隐藏指针的，从头到尾都是 U-05 补的那一句全局 `set`——也正是缺陷的来源。

## 修法：把"区域限定"自己实现出来

不去改事件分发（改成 `sendEvent` 是大手术，会牵动输入链路的一切既有结论），
而是自己维护"隐藏/恢复"的往返：

```cpp
static bool pointerIsOverOurWindow() {
    const NSPoint p = [NSEvent mouseLocation];
    if (!NSPointInRect(p, gWindow.frame)) return false;
    // 问 WindowServer：这个点最上面是谁的窗口
    const NSInteger top = [NSWindow windowNumberAtPoint:p belowWindowWithWindowNumber:0];
    return top == gWindow.windowNumber;
}

static void syncGlobalCursorForPointer() {
    const bool wantBlank = gSystemCursorHidden && pointerIsOverOurWindow();
    const bool showingBlank = systemCursorIsBlank();   // +[NSCursor currentSystemCursor]
    if (wantBlank && !showingBlank) [concordInvisibleCursor() set];
    else if (!wantBlank && showingBlank) [[NSCursor arrowCursor] set];
}
```

三个要点：

1. **判据用 WindowServer 的事实**（`windowNumberAtPoint:`），不用 AppKit 的
   `isActive/isKeyWindow`——那两个在上面那张表里是 0，而且它们是"我设过"式的
   缓存，窗口被别的应用盖住时不会立刻更新。
2. **状态用"系统此刻真正在显示的游标"**（`currentSystemCursor` 是不是那张 1×1），
   不用自己的标志位——标志位一旦和事实脱节（比如 AppKit 自己把游标改回箭头），
   就再也收敛不回来。
3. **每帧收敛**：`pumpEvents()` 开头一次 + `present()` 末尾一次。前者覆盖"没有事件
   也要恢复"，后者覆盖"主菜单阻塞在 GetMessageW 上、pump 几秒才转一次"。

原先 U-05 在每个事件上无条件 `set` 的那一段**删掉**——它的职责被收敛器接管了。

## 验证

自检 `CONCORD_CURSOR_SELFTEST=1`（`ra2mac_docs` 之外唯一的额外产物是
`/tmp/concord-cursor-selftest.log`，因为用 LaunchServices 启动的进程 stderr 是 /dev/null）。
断言两条：指针在窗口内 → 系统游标必须是那张 1×1；移到窗口外 → 必须不是。

修复前（同一台机器、同一个二进制）：

```
[cursor] inside  pointer=-134,1871 inWindow=1 cursor=1x1 hidden=1 ok=1
[cursor] outside pointer=438,1871 outsideWindow=1 cursor=1x1 hidden=1 ok=0   ← 用户看到的现象
[cursor] done: failures=1 skips=0
```

修复后（终端直接启动，立刻跑）：

```
[cursor] inside pointer=780,543 inWindow=1 overUs=1 top=2942 ours=2942 cursor=1x1 hidden=1 sync=25 want=1 ok=1
[cursor] outside pointer=1352,543 outsideWindow=1 cursor=28x40 hidden=0 ok=1
[cursor] done: failures=0 skips=0
```

再用 LaunchServices（`open`）走真实启动路径复跑，同样两条 `ok=1 / failures=0`
（这条路径上 `appActive=1 windowKey=1`，说明激活只有在 LaunchServices 拉起时才会发生）。

回归：

```
PASS=5 KNOWN-RED=6 RED-NEW=0  共 11 条
```

与改动前逐条一致。dist 已重打包（`pack-dist.sh`，20:55），包里二进制即修复版。

## 已知边界

- 判据是"指针点在**我们窗口**上"，所以指针移出窗口的**那一刻**基本是立刻恢复的
  （60Hz 收敛），但如果进程卡住不刷帧也不 pump，恢复会跟着卡——这与"画面冻住"
  是同一个失效模式，不单独处理。
- 窗口被别的应用盖住时，指针在"我们的框内"也不会隐藏（`overUs=0`），这是有意的：
  用户看的不是我们的画面，就不该让他的指针消失。
