# U-11 指针捕获：把鼠标「关」在游戏里（按需捕获）

日期：2026-11-11 21:00

## 建议与取舍

用户提的方案：

> 当鼠标在 app 框内的时候，隐藏了系统图标。鼠标移出去就看不到了。这里也可以参考
> vmware 的设计。游戏 focus 状态的时候，游戏指针不能移出屏幕，系统指针也可以限制
> 不能移出去。使用组合快捷键释放指针，让游戏 unfocus，游戏内的游戏光标可以不动。
> 系统指针释放，可以往外移动。

第一句是缺陷，已按 U-10 修掉（`[NSCursor set]` 是全局设置，移出窗口不撤销）。
后两句是这套捕获交互，本文处理。

### macOS 没有"把光标限制在窗口内"这个 API

第三方应用在 macOS 上做不到"指针撞到窗口边界被挡住"。能做的只有**相对模式**：

```cpp
CGAssociateMouseAndMouseCursorPosition(false);   // 硬件指针从此不再跟鼠标走
```

之后物理鼠标照常产生 `NSEvent.deltaX/deltaY`，但屏幕上的箭头**完全不动**。
把这套 delta 累加成"虚拟指针"，再让游戏用它画自己的光标——这就是 VMware 和所有
Mac 游戏所谓的"抓住鼠标"。所以「游戏指针不能移出屏幕」在 macOS 上的落地形式是
**「指针停住 + 游戏接管」**，而不是"被边框挡住"。

顺带一点：**全屏模式根本不需要捕获**。窗口就是屏幕，指针物理上出不去，
边缘滚动天然可用——这也是大多数 Mac 游戏的处理方式。捕获只在窗口模式有意义。

### 决策：按需捕获

窗口模式是否默认抓住指针，是这件事唯一真正的分歧：

- **默认捕获**（VMware 老行为）：连贯，但用户想点别的窗口必须先按热键，
  很容易以为"鼠标坏了"；
- **按需捕获**（本轮采纳）：默认自由，需要时手动抓、随时放开、点回自动再抓。

用户选择按需捕获。

## 实现

三态（`gPointerState`）：

| 状态 | 进入方式 | 行为 |
|---|---|---|
| `Free` | 默认 | 指针自由出入；窗口内隐藏系统箭头（U-04/U-10 常态） |
| `Captured` | `⌃⌘G` | 硬件指针钉在窗口中心并冻结；游戏光标按 delta 走 |
| `Released` | `⌃⌘` | 硬件指针接回游戏光标处、恢复关联；系统箭头可见，游戏光标停在原地 |

几个关键细节：

1. **⌃⌘ 组合在 `emit()` 最前面拦掉**，且发生在 `syncModifierState` 之前——
   否则 Ctrl 会被当成"强制攻击"修饰键喂给游戏。其余 ⌃⌘ 组合一律吞掉。
   选 ⌃⌘ 是因为本游戏不用 Command（`syncModifierState` 只映射 Shift/Ctrl/Option/CapsLock），
   Ctrl 单独是强制攻击，两者组合不冲突；VMware Fusion 的释放键也是 ⌃⌘。
2. **delta 累积要翻 y 并夹边**：`NSEvent.deltaY` 朝上为正，表面坐标朝下为正，
   所以 `y -= deltaY`；夹在 `[0, 表面尺寸-1]`，拖到边上就贴住、不会溢出。
3. **释放时先恢复关联再 warp**，顺序反了 warped 的位置不生效。
4. **点回窗口自动再抓**：`Released` 态下的鼠标按下会先 `capturePointer()`，
   并把虚拟指针设成点击位置（否则会从表面中心跳一下）。
5. **三重兜底**（这是本轮最大的风险点——`CGAssociateMouseAndMouseCursorPosition`
   是进程级开关，漏恢复会让整机鼠标动不了，只能强杀）：
   - 正常释放路径自己恢复；
   - `shutdown()` 调用 `ensurePointerAssociationRestored()`；
   - `std::atexit` 兜底（进程以任何方式结束）；
   - 自测里的 `std::_Exit` 路径也手动恢复（`_Exit` 不跑 atexit）。
6. **失焦即释放**：`windowDidResignKey` 里若还在捕获态就放人。

## 验证

自检 `CONCORD_CAPTURE_SELFTEST=1`：

```
[capture] captured
[capture] delta virtual=549,341 expect=549,341 ok=1
[capture] released pointer=780,527
[capture] release landed=1 want=780,527 now=780,527 state=2 ok=1
[capture] done: failures=0
```

- `delta` 那条断言的是**我们自己那一半**：投一条带 `delta=(37,-21)` 的合成
  `mouseMoved` 进队列，虚拟指针从表面中心 (512,320) 精确走到 (549,341)——
  横向 +37、纵向 +21（y 翻转对了），一步不差。
- `release` 那条断言释放后硬件指针**真的落在**游戏光标对应的屏幕点上，
  偏差 0px。
- `state=2` 说明释放后回到 `Released` 态。

回归 `PASS=5 KNOWN-RED=6 RED-NEW=0`，与改前逐条一致；dist 已重打包。

### 没能自动验的部分（必须人工确认）

**"捕获期间硬件指针真的不动"没法在进程内自动断言。** 试过
`CGWarpMouseCursorPosition` 推开再读位置——指针照样移动，因为 warp 是显式定位，
绕过关联开关。能自动证明的只有"我们的 delta 处理正确"和"释放落点正确"。
所以请手动验一条：

> 进游戏（窗口模式）→ `⌃⌘G` → 来回移动鼠标：**游戏光标动、屏幕上的箭头不动**，
> 指针不会跑到窗口外 → `⌃⌘` → 箭头出现在游戏光标处、可以自由移出窗口。
