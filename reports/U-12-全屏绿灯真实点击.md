# U-12 全屏绿灯：performClick 全绿，真实点击没反应

日期：2026-11-11 23:30

## 症状

用户：

> 全屏按钮不是真的全屏效果。只是窗口最大化了

而 U-09 的自测明明全绿（`affordance=1 viaButton=1 failures=0`），dist 包内复跑也一致。

## 根因：自测走的是程序化路径，真实点击根本到不了按钮

本项目**从不调用 `[NSApp sendEvent:]`**（U-10 已查清的事实）。这意味着
AppKit 的标题栏按钮点击响应链从来没被喂过事件——真实鼠标点绿灯，事件
被 pumpEvents 出队后直接进 `emit()`，被翻译成游戏输入吞掉，按钮的
action 永远不触发。

U-09 的自测用的是 `[zoom performClick:nil]`：这是**程序化直调 action**，
完全绕过事件链。所以它证明的只是「按钮的 action 接在全屏上」，证明不了
「用户点击能到达按钮」。这正是判定纪律里「绑定层全绿 ≠ 输入链路通」的
又一次应验——和 Ctrl+数字键那次（TeamKeySmoke 全绿而快捷键全废）同构。

红叉在 L10N-03 已经为同一件事补过命中（事件泵里显式命中 → performClose:），
绿灯漏掉了——U-09 只改了 `collectionBehavior`，没意识到事件链这一层。

## 修法（RuntimeAppleWindowSurface.mm，两处）

### 一、绿灯补命中（emit()，与红叉同构）

在红叉命中块之后加一段：down 落在绿灯上 → `gZoomButtonArmed = true` 并吞掉；
up 且 armed → 命中则 `[gWindow toggleFullScreen:]`（进入/退出同一动作，
全屏态再点即退回；退回发生在主循环栈里，满足 U-09 的时序前提），
吞掉配对的 up。不做最小化按钮，理由同红叉注释（缩进 Dock 收不到恢复点击）。

### 二、自测改走真实事件链

`CONCORD_FULLSCREEN_SELFTEST` 不再 `performClick:`，改为把一对合成的
LeftMouseDown/Up（location 取绿灯在窗口坐标中的中心）用 `[NSApp postEvent:]`
投进**真实事件队列**，完整走 pumpEvents → emit() → 命中 → toggleFullScreen:。
与红叉自测（CONCORD_CLOSE_SELFTEST）同一套做法。原「8 帧无 willEnter 则兜底
toggleFullScreen」的兜底逻辑保留，兜底生效会如实打印。

## 没能验证的

- WindowServer 投递这一段（真实硬件点击 → 队列）仍然无法合成：本机
  Accessibility 未授权，CGEventPost 被丢弃。`postEvent:` 验到的是队列之后的
  全链路（pump → 命中 → toggle），这是没有 AX 授权时能做到的最强判据。
- 「绿灯图标现在是展开箭头」的像素级验证依旧做不了（AX 子角色懒创建，返回 nil），
  形态判据仍是 collectionBehavior + 行为判据。

## 判定纪律增补

**performClick / 直调 action 类自测一律不算「用户路径通过」。**凡是「点了
没反应」类报障，先问事件有没有走到分发层（本项目没有 sendEvent，这一层
不存在），再问语义对不对。红叉、绿灯两次同坑，下一个标题栏交互（若加
最小化或别的）必须直接从 postEvent 链路起测。
